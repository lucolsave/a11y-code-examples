Autocomplete suggestions

Instructions

The autocomplete suggestions component works much like a native <select> element, so this example is based on our best-practice approach for building a custom select.

Search Input

The search form should be wrapped within the <search> element or use the role="search" attribute. The <input> element should use type="search". In addition to this, a couple of extra attributes should be considered:

  • role="combobox": Combines an input field with a popup providing possible values for that input field.
  • aria-activedescendant: An ID pointing to the currently active suggestion (if the user has an active selection). This also allows the user select an list item without losing focus on the input field.
  • aria-autocomplete="list": Indicates that inputting text could trigger predictions or suggestions. If the suggestion also appears after the caret in the input, use aria-autocomplete="both".
  • aria-expanded: Set to true or false depending on whether the suggestion popover is visible.
  • aria-controls: An ID pointing to the listbox of search suggestions. (Note: This element should always exist in the DOM, even if it is hidden initially).
  • autocomplete="off": Turns off automated assistance in filling out form field values.
  • aria-haspopup is not required becuase the element with the role combobox have an implicit aria-haspopup value of listbox.
  • Add a visually hidden <label> for the search input. The magnifying glass icon and the placeholder text “Search…” are enough as the visible label for sighted users, but the hidden label ensures screen readers announce it properly.
  • Add aria-hidden="true" to the <svg> that represents the magnifying-glass icon so screen readers ignore it and don't announce it.

When autocomplete results are available use up and down arrows to review and enter to select. Touch device users, explore by touch or with swipe gestures.

Also note that all form elements should have a <label>.

Suggestions

Suggestions should have the following attributes:

The suggestion container

  • role="listbox": Indicates a list of selectable options.

For each options

  • role="option": Announces the list item as an option to screen readers.

Navigation

  • Enter the proposals: Down arrow (from input to first suggestion)
  • Navigate between proposals: Up and down arrows (no Tab)
  • Exit proposals: Up arrow (from first item back to input)
  • Select a proposal: Use Space, Enter, Tab or Esc
  • After selection: Keep the focus on the input
  • Esc key: Closes the listbox
  • No item selected: Focus returns to input without clearing value
  • Left/Right arrows: Move the caret within the input without closing the listbox
